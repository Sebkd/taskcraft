## 1. Предложение

### Цель изменения

Ревью 0.1.0 и спайк `taskcraft-sebkd-24` нашли в публичном API ловушки и лишнюю сложность, которые компилятор не ловит:

- ручку очереди нужно взять **до** `Monitor::register`;
- наблюдатель, добавленный после регистрации, событий очереди не получает;
- тип ручки `QueueHandle<InMemorySource<String>, IdentityCodec<String>, String>` выписывается в каждом поле;
- трейт `Source` разросся до 11 методов, транспорт и хранилище реализуют разные половины;
- хранилище принимает любой кодек байтов, хотя работает только с `JsonCodec`;
- в корне пакета больше 60 имён.

Решения согласованы владельцем проекта (спайк, вопросы Q-1…Q-6). Все изменения несовместимы, поэтому выходят одним выпуском 0.2 с руководством по миграции.

### Объём реализации

Выпуск: 0.2.

**Реализует:**

- **Q-1:** `Monitor::register` возвращает пару «монитор, ручка очереди»; `Queue::handle` убирается.
- **Q-2:** `QueueHandle<Args>` — ручка со стёртыми источником и кодеком.
- **Q-3:** контракт источника делится на три трейта:
  - `Source` — опрос, ack, подписка, возможности;
  - `PushSource` — постановка, снятие;
  - `TaskStore` — исход, прогресс, статус, уведомления, отложенный повтор.

  Постановка в источник без `PushSource` — ошибка компиляции.
- **Q-4:** очередь хранилища со встроенным кодеком (`Queue::on_store`) и собственным типом сообщения хранилища.
- **Q-5:** модули `source`, `codec`, `observe`, `runnable`, `error`, `testing` и `prelude`.
- **Q-6:** наблюдатели передаются очередям при `run`.
- Руководство по миграции 0.1 → 0.2.

**Не входит:**

- Изменения поведения очередей.

**Зависит от заявок:** `worker-module-split` (переносить код после разделения воркера).
