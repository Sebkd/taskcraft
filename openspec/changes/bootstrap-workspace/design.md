## Context

В репозитории пока нет ни одного пакета Rust. Есть только `openspec/` и `.gitignore`. Заявка создаёт рабочее пространство пакетов, правила линтера, проверку зависимостей и CI, чтобы следующие заявки сразу писали код в готовую инфраструктуру.

Образцы:

- **statecraft-fsm**, та же семья. CI на GitHub Actions запускается push'ем в зеркало: разработка ведётся в Gitea, а на GitHub попадает push-зеркалом. Там же отдельная проверка MSRV, общие версии зависимостей в `[workspace.dependencies]`, лицензия MIT, автор `sebkd`.
- **apalis**, по разбору. Запрет небезопасного кода и развёрнутый набор правил clippy в `[workspace.lints]`, `.clippy.toml` с `msrv`, `deny.toml`, каталог `supply-chain/` для cargo-vet, отдельный workflow аудита.

Ограничения:

- Целевая спецификация: раздел 2.6 (MSRV 1.99, редакция 2024, MIT, репозиторий `https://github.com/Sebkd/taskcraft`) и 4.1 пп. 1, 5.
- Локальный тулчейн — 1.99 (override каталога через rustup; default stable на машине — 1.96.1). cargo-deny и cargo-vet установлены локально через `cargo install`; в CI их ставят workflow.
- PR открываются в Gitea, на GitHub приходят только push'и зеркала. Поэтому CI запускается на push в любую ветку, а не на `pull_request`.

## Goals / Non-Goals

**Goals:**

- Виртуальное рабочее пространство с пакетом ядра `taskcraft`. Новые пакеты добавляются без правки корневого манифеста.
- Общие правила линтера для всех пакетов; небезопасный код запрещён.
- CI: форматирование, clippy без предупреждений, тесты, документация без предупреждений, проверка MSRV, проверочная публикация, cargo-deny, cargo-vet.
- Лицензия, метаданные пакетов, README.
- Имя `taskcraft` занято на crates.io версией-заглушкой.

**Non-Goals:**

- Код библиотеки: начинается с `task-model-and-lifecycle`.
- Пакеты `taskcraft-kafka` и хранилища: создаются в своих заявках. Пустые пакеты-заглушки сейчас не заводятся, иначе их тоже пришлось бы публиковать.
- Автоматическая публикация по тегу: на первых версиях публикуем вручную (решение Q-12.1 spike).
- CHANGELOG: история изменений ведётся заявками OpenSpec, как в statecraft.

## Decisions

### Раскладка: виртуальное рабочее пространство и `crates/*`

**Решение**: корневой `Cargo.toml` без `[package]`, `members = ["crates/*"]`. Ядро лежит в `crates/taskcraft`. Следующие пакеты (`crates/taskcraft-kafka`, пакет хранилища) подхватываются автоматически.

**Обоснование**: пакетов будет несколько, и все равноправны. Виртуальный корень не превращает ядро в «главный» пакет, а глоб избавляет от правки корня в каждой заявке.

**Альтернативы**:
- Корень — пакет ядра, остальные — подкаталоги (как в statecraft) — отклонено: там второй пакет служебный (макросы), а здесь бэкенды равноправны ядру.
- Явный список `members` — отклонено: лишняя правка корня в каждой заявке-пакете.

### Общие метаданные и версии через `[workspace.package]` и `[workspace.dependencies]`

**Решение**:
- В `[workspace.package]`: `version`, `edition = "2024"`, `rust-version = "1.99"`, `license = "MIT"`, `authors = ["sebkd <sebkd80@gmail.com>"]`, `repository = "https://github.com/Sebkd/taskcraft"`.
- Внутренние зависимости между пакетами объявляются в `[workspace.dependencies]` с `path` и `version`.

**Обоснование**: критерий заявки «версии зависимостей между пакетами совпадают с версиями пакетов». У apalis в dev-зависимостях стояла устаревшая версия соседнего пакета (P-6), и сборку спасал только `path`. Единый источник версии плюс проверочная публикация в CI ловят такое расхождение.

**Альтернативы**:
- Версии в каждом манифесте отдельно — отклонено: это ровно путь к P-6.

### Правила линтера в `[workspace.lints]`

**Решение**:
- `[workspace.lints.rust]`: `unsafe_code = "forbid"`, `missing_docs`, `missing_debug_implementations`, `unreachable_pub` и группа `rust_2018_idioms` — уровень `warn`.
- `[workspace.lints.clippy]`: набор правил apalis (await_holding_lock, dbg_macro, todo, redundant_clone, needless_pass_by_value, use_self, uninlined_format_args и остальные из их списка) — уровень `warn`.
- Каждый пакет подключает правила строкой `lints.workspace = true`.
- В CI clippy запускается с `-D warnings`, поэтому `warn` там становится ошибкой.
- `.clippy.toml`: `msrv = "1.99"`.

**Обоснование**: `forbid` нельзя ослабить атрибутом внутри пакета, и это даёт инвариант спецификации 2.3.23 п. 3. Уровень `warn` вместе с `-D warnings` в CI не мешает локальной итерации, но не пропускает предупреждения в основную ветку.

**Альтернативы**:
- Взять правила apalis вместе с `type_complexity = "allow"` — отклонено. Разбор (A-9) прямо называет вес дженериков проблемой формы. Глобальное разрешение прячет её, поэтому `type_complexity` остаётся на уровне по умолчанию, и сложные типы придётся выносить в псевдонимы.
- `deny` прямо в манифесте — отклонено: ломает локальную сборку на каждом незаконченном черновике.

### Проверка зависимостей: cargo-deny и cargo-vet

**Решение**:
- `deny.toml` проверяет четыре вещи:
  - `advisories` — известные уязвимости; заменяет отдельный cargo-audit, база RustSec та же.
  - `licenses` — разрешены MIT, Apache-2.0, Apache-2.0 WITH LLVM-exception, Unicode-3.0, ISC, BSD-3-Clause, Zlib.
  - `bans` — `multiple-versions = "warn"`.
  - `sources` — только crates.io.
- cargo-vet: каталог `supply-chain/`, созданный `cargo vet init`, с импортом аудитов крупных организаций (Mozilla, Google, Bytecode Alliance, ZcashFoundation). В CI выполняется `cargo vet --locked`.

**Обоснование**: спецификация 4.1 п. 5 требует проверять уязвимости и лицензии; это делает cargo-deny. Решение spike T-01 включает и vet. Сейчас зависимостей нет, и подключить vet дешевле всего; добавлять его позже значит разбирать сразу всё дерево.

**Альтернативы**:
- cargo-audit отдельным шагом, как у apalis — отклонено: дублирует `cargo deny check advisories`.
- Без cargo-vet — отклонено: противоречит решению spike. Цена (риск ниже) принята осознанно.

### `Cargo.lock` в репозитории

**Решение**: `Cargo.lock` коммитится.

**Обоснование**: `cargo vet --locked` и воспроизводимость CI требуют lock-файл. Cargo с 2023 года рекомендует коммитить его и для библиотек; потребители библиотеки его не видят.

**Альтернативы**:
- Игнорировать, как в statecraft — отклонено: тогда cargo-vet и проверки зависимостей идут по каждый раз новому дереву.

### CI: два workflow на GitHub Actions

**Решение**:
- `.github/workflows/ci.yml` — на `push` в любую ветку и `workflow_dispatch`. Задания:
  - `check` на stable: `cargo fmt --all --check`; `cargo clippy --workspace --all-targets --all-features -- -D warnings`; `cargo test --workspace --all-features`; `cargo doc --workspace --no-deps --all-features` с `RUSTDOCFLAGS=-D warnings`; `cargo publish --dry-run` для каждого публикуемого пакета.
  - `msrv` на 1.99: `cargo check --workspace --all-features` без `--all-targets`, как в statecraft.
- `.github/workflows/supply-chain.yml` — на `push` при изменении `**/Cargo.toml`, `Cargo.lock`, `deny.toml`, `supply-chain/**`, плюс ежедневно по расписанию. Задания: cargo-deny и cargo-vet.

**Обоснование**: push-зеркало пушит все ветки, а PR живут в Gitea, поэтому на GitHub нет событий `pull_request` от наших веток. Ежедневный запуск аудита ловит новые уязвимости в уже зафиксированных зависимостях без изменений в коде.

**Альтернативы**:
- Только `main` и `pull_request`, как в statecraft — отклонено: рабочие ветки до слияния вообще не проверялись бы.
- Gitea Actions — отклонено решением Q-12.1 spike.

### Версия-заглушка и занятие имени

**Решение**:
- Версия рабочего пространства — `0.0.0`.
- В README и описании пакета сказано, что это резерв имени и рабочая версия будет `0.1.0`.
- Публикацию `cargo publish -p taskcraft` выполняет владелец репозитория вручную своим токеном crates.io. Опубликованную версию нельзя удалить, только отозвать (yank).

**Обоснование**: решение Q-12 spike — занять имя сразу после каркаса. Публикация необратима и требует личного токена, поэтому это ручной шаг.

**Альтернативы**:
- Ждать первой рабочей версии — отклонено решением Q-12.

## Risks / Trade-offs

| Риск | Последствия | Mitigation |
|------|------------|------------|
| cargo-vet требует аудита или исключения на каждую новую зависимость | Каждая заявка с новой зависимостью добавляет записи в `supply-chain/` | Импорт аудитов крупных организаций покрывает tokio, tower, serde и tracing; остальное — `cargo vet regenerate exemptions` осознанным шагом в той же заявке |
| Без `type_complexity = "allow"` clippy будет ругаться на сложные типы в контрактах | Больше псевдонимов типов | Желаемый эффект (A-9); точечный `#[allow]` с комментарием допустим |
| `missing_docs` на раннем этапе | Много шума при черновиках | Только `warn`; в CI ошибка, локально нет |
| Новая версия stable добавит правило clippy | CI станет красным без изменений в коде | Чинится отдельным коммитом; MSRV-задание от этого не зависит |
| Опубликованную заглушку нельзя удалить | Версия 0.0.0 навсегда в реестре | Это и есть цель — резерв имени; содержимое минимальное и честное |

```
taskcraft/  (виртуальное рабочее пространство)
├── Cargo.toml          [workspace] members = ["crates/*"]

│   ├── ci.yml            fmt, clippy, test, doc, publish --dry-run, msrv

    └── taskcraft/      ядро; дальше: taskcraft-kafka, пакет хранилища
        ├── Cargo.toml
        ├── README.md -> ../../README.md (через `readme` в манифесте)
        └── src/lib.rs
```

## Детали реализации

### Алгоритмы

Нет.

### Обработка edge cases

| Ситуация | Поведение |
|----------|----------|
| В пакете появляется `unsafe` | Ошибка компиляции: `forbid` нельзя переопределить через `allow` |
| Новый пакет забыл `lints.workspace = true` | Шаг CI проверяет, что строка есть в каждом `crates/*/Cargo.toml`, и падает без неё |
| Новая зависимость без аудита cargo-vet | Задание supply-chain падает с подсказкой `cargo vet` |
| Зависимость с лицензией вне списка | cargo-deny падает на `licenses` |
| Зависимость из git или другого реестра | cargo-deny падает на `sources` |
| Пакет без `description` или с несовпадающей версией внутренней зависимости | `cargo publish --dry-run` падает |
