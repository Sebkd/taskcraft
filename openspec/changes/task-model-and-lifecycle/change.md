## 1. Предложение

### Цель изменения

Зафиксировать первую из публичных форм библиотеки — задачу и её состояния. Статус задачи — общий язык для запроса статуса, метрик и хуков; пока он не определён, остальные контракты нечем выразить.

Метаданные задачи вводятся сразу типизированными: у каждого сценария свои типы, ошибка разбора видна, а не уходит в значение по умолчанию. Это закрывает дефект apalis, где метаданные стали строковым «ключ — значение» с молчаливым откатом при ошибке.

### Инициатор

Разработка первой версии taskcraft (ветка `taskcraft/sebkd-1`). Требования первого потребителя — спецификация, раздел 1.1.

### Затронутые компоненты

- [x] Ядро `taskcraft`: задача, метаданные, реестр типов метаданных, состояния задачи, результат постановки, статус

### Приоритет

критичный

### Обратная совместимость

Да: новая функциональность, публичных версий библиотеки ещё нет.

### Объём реализации

Спецификация 0.1 уже описывает целевое поведение (раздел 1.1, «Статус реализации»). Эта заявка поведение не меняет, а реализует перечисленные разделы. Поэтому разделы 2–15 ниже содержат только уточнения спецификации; где их нет — «Нет изменений.».

**Реализует:**

- 1.2 — глоссарий
- 2.4.1 — состояния и переходы задачи, запрещённые переходы
- 2.7.1–2.7.4 — задача, внешнее представление метаданных, результат постановки, статус
- 2.3.17 — метаданные: один тип — одно значение, реестр, ленивый разбор, неизвестные имена, зарезервированное имя
- 2.11.4 — причины в исходах

**Не входит:**

- Исполнение переходов воркером — `worker-loop-and-supervision`
- Извлечение метаданных в обработчике — `handler-error-classification`

**Зависит от заявок:** `bootstrap-workspace`

| # | КОГДА | ТОГДА |
|---|-------|-------|
| 1 | Попытка выполнить переход, отсутствующий в таблице 2.4.1 | Переход отклоняется; состояние задачи не меняется |
