## 1. Предложение

### Цель изменения

Без аренды задачу возвращает в очередь только тот же процесс при рестарте (2.3.19 п. 1). Если процесс выведен из эксплуатации — уменьшили число подов, сменили схему имён, — его захваченные задачи остаются «в работе» навсегда.

Это соответствует спецификации, но в эксплуатации так теряется работа, и никакого инструмента для этого случая нет.

### Инициатор

Код-ревью 0.1.0, бэклог код-ревью 0.1.0 (`docs/taskcraft-backlog_code-review-0.1.0.md`, локальный): BL-07.

### Затронутые компоненты

- [x] Пакет `taskcraft-postgres`: операция администратора, журнал при старте

### Приоритет

средний

### Обратная совместимость

Да: новая функциональность.

### Объём реализации

Выпуск: до пилота.

**Реализует:**

- `PgStore::release_process(id)`: вернуть в очередь задачи процесса, чья отметка «жив» устарела (старше двух интервалов); для живого процесса — ошибка «идентификатор процесса занят».
- При старте: WARN, если в хранилище есть задачи процессов, не отмечавшихся дольше заданного порога.
- Документация: на платформах с переменным числом процессов включать аренду.

**Не входит:**

- Автоматический возврат без аренды: противоречит 2.3.19 п. 4 («возраст — не признак сироты»).

**Зависит от заявок:** `store-schema-and-indexes`.

## 2. Бизнес-логика

**ADDED** — 2.3.19 п. 6:

> Задачи процесса, выведенного из работы, возвращает в очередь операция администратора «вернуть задачи процесса» — только если отметка «жив» этого процесса устарела. Хранилище при старте предупреждает о задачах процессов, не отмечавшихся дольше порога.
