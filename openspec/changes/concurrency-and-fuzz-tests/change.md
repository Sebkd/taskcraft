## 1. Предложение

### Цель изменения

Конкурентность проверяется тестами на виртуальном времени — то есть одним порядком событий из многих. Входные данные кодеков на устойчивость не проверяются. Сбой процесса везде имитируется `abort()` задачи монитора, а не настоящим падением.

### Инициатор

Код-ревью 0.1.0, бэклог код-ревью 0.1.0 (`docs/taskcraft-backlog_code-review-0.1.0.md`, локальный): BL-22, BL-23, BL-24.

### Затронутые компоненты

- [x] Тесты ядра и пакетов
- [x] CI: job с сервисами

### Приоритет

средний

### Обратная совместимость

Да: поведение библиотеки не меняется.

### Объём реализации

Выпуск: параллельно.

**Реализует:**

- `loom` для неделимого приёма в реестр и захвата пулов по порядку имён.
- `proptest`: последовательности «постановка / отмена / исход / остановка» с проверкой инвариантов 1.3.6, 1.3.8, 1.3.9.
- `cargo fuzz` для `JsonCodec::decode`, `KafkaJsonCodec::decode` и разбора метаданных: ни паники, ни зависания.
- Интеграционный тест: дочерний процесс, `kill -9` посреди задачи, рестарт, итог по 2.2.9 и 2.2.12 (Kafka и PostgreSQL).

**Не входит:**

- Фаззинг в CI на постоянной основе (только короткий прогон).

**Зависит от заявок:** нет.
