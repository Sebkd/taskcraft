## Context

`PgSource::requeue` (`crates/taskcraft-postgres/src/source.rs:355`) одним `UPDATE` возвращает задачу из `failed`/`panicked` в `queued` и очищает `retries`, `reason`, `owner`, `lease_until`, `next_delivery`, но не `cancel_requested`.

Флаг ставит `PgSource::remove` (`source.rs:330`) для живой задачи. Читает его обслуживание хранилища (`store.rs:662`, `:673`) при продлении аренд и проверке задач процесса и сообщает `Notice::CancelRequested` один раз на доставку: учёт `Held::tasks` (`store.rs:345`) живёт, пока задача удерживается, и освобождается при завершении (`source.rs:134`).

Гонка: отмену запросили во время попытки, попытка упала раньше, чем обслуживание прочитало флаг. Задача в «Ошибке» с `cancel_requested = true`. После `requeue` следующий владелец при первом же продлении получает запрос отмены, и повторный запуск отменяется.

## Goals / Non-Goals

**Goals**
- `requeue` начинает новый запуск без запроса отмены прошлого.

**Non-Goals**
- Сброс флага при возврате задач рестартом (`give_back`), по истёкшей аренде и в `release_process`: там это та же доставка, и запрос должен дойти до следующего владельца.
- Изменение учёта `Held::tasks`: он и так сбрасывается с каждой доставкой.

## Decisions

### D-1. Сбрасывать в `requeue`, а не при завершении

`cancel_requested = false` добавляется в `SET` того же `UPDATE` в `requeue`.

Альтернатива — сбрасывать флаг при любом терминальном исходе в `complete`. Отклонена: она трогает горячий путь каждой задачи ради редкого случая, а терминальной задаче флаг не мешает. Единственный путь из терминального состояния обратно в работу — `requeue` (переход 2.4.1.14), его и правим.

### D-2. Тест — на уровне источника и монитора

Тест в `crates/taskcraft-postgres/tests/store.rs` повторяет пробу из ревью и проверяет поведение:

1. Хранилище с арендой; через `TaskStore` напрямую: `push` задачи `n = 4` (спит час) → `poll` → `remove` (ответ «запрошена отмена») → `complete` с «Ошибкой» → `requeue`.
2. Колонка `cancel_requested` — `false`.
3. Монитор на той же очереди берёт задачу. Через 3 интервала продления (больше `cancel_grace`) она всё ещё «В работе», а не «Отменена».

Без исправления п. 3 падает: продление сообщает запрос отмены, через `cancel_grace` задача отменяется.

### D-3. Версия

Исправление только в `taskcraft-postgres`, API не меняется. Версия поднимается до 0.3.1 при выпуске, отдельной веткой, как 0.3.0.

## Risks / Trade-offs

- Запрос отмены, пришедший между падением попытки и `requeue`, теряется. Это верно: он относился к упавшему запуску, а `requeue` — явное решение оператора запустить задачу снова.
