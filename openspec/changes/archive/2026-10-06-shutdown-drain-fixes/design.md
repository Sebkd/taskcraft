## Context

`run_worker` (`worker.rs`) после цикла приёма вызывает `drain(...)`. Ветвь выбирается так: `shutdown_timeout = graceful.then_some(...)`. При закрытии источника таймаута нет, и `drain` ждёт `join_next` до конца, не глядя на `ctx.stop`.

При прерывании по льготному времени `drain` пишет WARN `task/aborted`, удаляет задачи из реестра и вызывает `abort_all()` — исхода и события `Finished` нет.

`QueueHandle::push` проверяет `tasks.is_closing()` до записи в источник; между проверкой и записью воркер может закончить приём.

---

## Goals / Non-Goals

**Goals:**

- Сигнал остановки во время дренажа после закрытия источника включает таймаут остановки, признак отмены и льготное время (переход 2.4.2.13, критерий №51).
- Прерванная задача даёт исход «Отменена» с причиной «остановка»: запись `task/finished`, событие `Finished`, метрика (критерий №52).
- Постановка, совпавшая с остановкой, либо принята воркером, либо отвечает «очередь останавливается» без задачи в источнике (критерий №53).

**Non-Goals:**

- Итог остановки 2.7.6 — без изменений.

---

## Decisions

### Дренаж слушает сигнал остановки всегда

**Решение**: `drain` получает `stop: &CancellationToken` и признак «приём закончен сигналом».

- Сигнал уже был — сразу ветвь с таймаутом, как сейчас.
- Источник закрыт — ждать задачи, пока не придёт сигнал:
  - все задачи закончились раньше — выход без таймаута;
  - пришёл сигнал — с этого момента таймаут остановки, затем признак отмены и льготное время. Задачи, закончившиеся до сигнала, учитываются как сейчас.

Новая функция `wait_all_or_stop` — аналог `wait_all` с остановкой по токену вместо срока.

### Исход прерванной задачи до `abort_all`

**Решение**: перед `abort_all` для каждой оставшейся задачи из `ids`:
- номер попытки берётся из реестра (`tasks.status(id)`);
- `log_outcome(…, Cancelled, CancelledByShutdown)` — запись `task/finished`;
- событие `Finished { state: Cancelled, reason: CancelledByShutdown }`;
- затем `tasks.remove`.

Ack не выполняется — как у отмены остановкой. `drain` получает `&Observers`.

### Гонка постановки — откат из нестойкого источника

**Решение**: в `QueueHandle::push` после ответа источника «записано» — повторная проверка `is_closing()`. Если очередь уже останавливается и источник не хранилище (`AckPointSupport::Fixed` отсутствует):
- `source.remove(id)`;
- `Removed` → ошибка «очередь останавливается»;
- иначе задачу уже выдал опрос — ответ «поставлена»: воркер её принял.

Для хранилища отката нет: задача сохранится и будет выполнена после рестарта, ответ «поставлена» верен.

**Обоснование**: проверка до записи остаётся быстрым путём; повторная после записи закрывает окно.

### Уточнение критерия №53

Формулировка заявки «задача исполнена до остановки» сильнее, чем можно гарантировать: принятая воркером задача может быть отменена остановкой. Критерий в спецификации: «либо поставлена и принята воркером, либо ошибка „очередь останавливается“ и задачи в источнике нет».

## Risks / Trade-offs

| Риск | Последствия | Mitigation |
|------|------------|------------|
| Задача закончилась между снимком `ids` и `abort_all` | Двойной исход | Снимок и `abort_all` без `await` между ними; закончившиеся до снимка уже удалены из `ids` |
