## 1. Предложение

### Цель изменения

Связать задачу с многошаговым процессом, не заводя в движке собственного механизма процессов. Обработчик возвращает запускаемое — расширяемый публичный контракт «запустить, мягко остановить, дождаться исхода, перевести исход». Паника внутри — штатный исход, отмена задачи — мягкая остановка.

Первая версия даёт адаптер к statecraft-fsm в его нынешнем виде. Общая реализация для всех автоматов с терминальным исходом появится за возможностью сборки «statecraft» после отдельной заявки в репозитории statecraft-fsm.

### Инициатор

Разработка первой версии taskcraft (ветка `taskcraft/sebkd-1`). Требования первого потребителя — спецификация, раздел 1.1.

### Затронутые компоненты

- [x] Ядро `taskcraft`: контракт запускаемого, адаптер statecraft-fsm, возможность сборки «statecraft»
- [x] Внешне: заявка `terminal-state-outcome` в statecraft-fsm (вне этого репозитория)

### Приоритет

средний

### Обратная совместимость

Да: новая функциональность, публичных версий библиотеки ещё нет.

### Объём реализации

Спецификация 0.1 уже описывает целевое поведение (раздел 1.1, «Статус реализации»). Эта заявка поведение не меняет, а реализует перечисленные разделы. Поэтому разделы 2–15 ниже содержат только уточнения спецификации; где их нет — «Нет изменений.».

**Реализует:**

- 2.3.21 — запускаемое

**Не входит:**

- Изменение statecraft-fsm — отдельная заявка в его репозитории; общая реализация делается после её влития

**Зависит от заявок:** `handler-error-classification`, `task-registry`
