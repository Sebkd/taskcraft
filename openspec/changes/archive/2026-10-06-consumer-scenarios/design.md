## Context

Все функциональные заявки реализованы. Критерии раздела 3 покрыты тестами по заявкам; большинство тестов ссылается на номер критерия. Нет сквозной проверки трёх сценариев первого потребителя и сводной таблицы покрытия.

Сверка с разделом 3 показала:

| Что | Состояние |
|-----|-----------|
| №6 — паника при оставшихся попытках, остальные задачи продолжают | Только по частям: `attempt.rs`, счётчик паник в `tests/metrics.rs`. Сквозного теста нет |
| №20 — сигнал остановки во время сна воркера | Проверено на `Poller`, на воркере — нет |
| №24 — собственный момент ack | Журнальная часть есть; табличная (та же постановка принята) — нет |
| №29 — неизвестные метаданные при «отложить» | Проверено на кодеке, через воркер — нет |
| №37 — каждое правило 2.10 | Разбросано по unit-тестам; часть правил не проверена, найдены расхождения (ниже) |
| №47 — переполнение in-memory источника | Проверено на источнике, через ручку очереди — нет |

Расхождения с 2.10:
1. `InMemorySource::new(0)` паникует (`assert!`), а не возвращает ошибку конфигурации. Это нарушает и 2.10, и инвариант 1.3.19: clippy не ловит `assert!`.
2. Хранилище: сообщения «heartbeat interval must be below half the lease duration» и «process id must not be empty» расходятся с 2.10 («…must be less than half the lease», «task store requires a process id»).
3. «Политика «отказать» без хука» в API невыразима: `reject_with(hook)` требует хук.
4. Ёмкость источника в 2.10 стоит в строке длительностей с сообщением «duration must be positive».

## Goals / Non-Goals

**Goals:**

- Три сценария первого потребителя (критерии заявки №1–№3).
- Сквозные тесты для №6, №20, №24, №29, №47; тест №37 по всем строкам 2.10.
- Таблица покрытия раздела 3 (критерий заявки №4) — в этом документе.
- Исправление расхождений с 2.10.

**Non-Goals:**

- Запускаемые примеры `examples/` — заявка `examples-catalog` (E-1…E-15), она возьмёт сценарии отсюда.
- Внедрение в сервисы первого потребителя.

## Decisions

### Сценарии — интеграционные тесты на виртуальном времени

**Решение**: `crates/taskcraft/tests/consumer_scenarios.rs`:

| Сценарий | Проверка |
|----------|----------|
| «Долгая задача» | Лимит 2, «отказать» с ответом отправителю через хук, задачи по часу, пауза повтора 5 мин, сигнал остановки. Отказ без блокировки приёма; остановка прерывает паузу без продвижения часов |
| «Ресурсоёмкая задача» | Пулы «unpack» (2) и «pack» (1), задачи берут оба; статус и отмена по идентификатору. Параллельность ограничена пулами; разрешения возвращены после отмены; статусы по 2.4.1 |
| «Задача-автомат» | Автомат statecraft-fsm (dev-dependency); ack «после приёма»; записи потребителя — общая карта «задание → этап». Сбой — `abort()` задачи монитора посреди работы автомата. Второй монитор с хуком восстановления по записям поднимает задачу, автомат доводит её до исхода |

**Обоснование**: тесты проверяются в CI и детерминированы на виртуальном времени. Запускаемые примеры с выводом — отдельная заявка; дублировать их здесь незачем.

### Сводная таблица покрытия

**Решение**: таблица — раздел «Покрытие раздела 3» ниже. Новые тесты ссылаются на номер критерия в комментарии, как и прежние.

### Критерий №37 — один тест на все строки 2.10

**Решение**:
- `crates/taskcraft/tests/config.rs`: по одной проверке на каждую строку 2.10, в которой есть ядро; сообщение ошибки содержит текст из 2.10.
- Строки пакетов — в их unit-тестах: ожидание опроса Kafka; аренда, heartbeat и идентификатор процесса хранилища.
- «Отказать» без хука — пометка в таблице «невыразимо в API».

### Ёмкость in-memory источника — ошибка вместо паники

**Решение**: `InMemorySource::new(capacity) -> Result<Self, ConfigError>`; новый вариант `ConfigError::InvalidCapacity` с сообщением «capacity must be at least 1». `Default` (10 000) остаётся без `Result`.

**Обоснование**: инвариант 1.3.19 и 2.10 — ошибка конфигурации, а не падение. Сообщение «duration must be positive» для ёмкости вводит в заблуждение; строку 2.10 разделить.

**Альтернативы**:
- `new(NonZeroUsize)` — отклонено: ноль невыразим, но вызов многословен, и это расходится с остальными построителями, которые возвращают `ConfigError`.

### Сообщения хранилища — по тексту 2.10

**Решение**:
- «heartbeat interval must be less than half the lease»;
- `PgStoreError::EmptyProcessId` — «task store requires a process id».

### `assert!` в рабочем коде — под запретом 1.3.19

**Решение**: тест-сканер исходников (как `library_sources_print_nothing`) запрещает `assert!`, `assert_eq!`, `assert_ne!` в рабочем коде всех пакетов, вне `#[cfg(test)]` и doc-комментариев; `debug_assert!` разрешён. Пункт 4.3 п. 9 дополнить.

**Обоснование**: clippy не имеет линта на `assert!`, а это та же паника.

## Risks / Trade-offs

| Риск | Последствия | Mitigation |
|------|------------|------------|
| `InMemorySource::new` меняет сигнатуру | Правка ~18 мест в тестах и документации | Публичных версий нет |
| Сбой процесса имитируется `abort()` монитора | Не настоящее падение процесса | Для in-memory источника и хука восстановления разницы нет: состояние процесса теряется так же; хранилище проверено отдельно |
