## Context

Ядро умеет in-memory и журнальные источники. Контракт источника (`Source`) знает опрос, ack, постановку, отложенный повтор и `remove`; момента ack «фиксированный» (`AckPointSupport::Fixed`) ещё никто не объявлял. Реестр живых задач, отмена, восстановление хуком, наблюдатель — готовы.

Требования:
- **2.6 «Пакет хранилища задач»**, **2.7.5** — логическая модель, **2.8 «Хранилище и аренда»**.
- **2.3.9 п. 6** — ack хранилища = запись терминального статуса или «Отложена», всегда.
- **2.3.11 п. 4** — «уже завершена» до истечения срока хранения.
- **2.3.19 пп. 1, 2, 5** — сироты своего процесса при рестарте; уникальность идентификатора процесса.
- **2.3.20** — аренда и heartbeat; **2.3.25** — опрос с захватом; **2.1.2.18**, **2.2.9** — подхват по аренде.
- **2.1.2.14 п. 4**, **2.1.2.15 пп. 4–6** — статус и отмена через хранилище.
- **Критерии:** №30, №31, №43, №44, №45; критерии заявки №1–№4.

Решения, согласованные с владельцем проекта: драйвер — sqlx 0.9 (у первого потребителя sea-orm 2.x на sqlx 0.9); подключение строкой либо готовым `PgPool`, в том числе из sea-orm.

## Goals / Non-Goals

**Goals:**

- Расширение контракта источника в ядре для хранилищ.
- Пакет `crates/taskcraft-postgres`: `PgStore`, `PgStoreBuilder`, `Lease`, `PgSource`, `PgReceipt`, `PgStoreError`.

## Decisions

### Контракт источника для хранилищ (ядро)

**Решение**: новые методы `Source` с реализацией по умолчанию — прочие источники не меняются:

| Метод | По умолчанию | Хранилище |
|-------|--------------|-----------|
| `complete(receipt, Completion { state, reason })` | `ack` | Записать терминальный статус и причину |
| `progress(receipt, Progress { state, attempt, retries })` | ничего | Записать состояние и счётчики (сквозной номер попытки) |
| `status(id)` | `None` | Статус из хранилища, включая терминальные и чужие задачи |
| `notices()` | `None` | Канал `Notice`: `CancelRequested`, `LeaseLost`, `TakenOver` |
| `remove(id) -> Withdrawal` (было `bool`) | `NotFound` | `Removed` / `CancelRequested` / `Finished` / `NotFound` |

`PushResult::Finished(state)` → `PushOutcome::AlreadyFinished`. `TaskStatus::new`, `with_times`, `with_reason`, `with_owner` стали публичными: источник строит статус сам.

**Обоснование**: хранилищу нужно знать исход, а не только факт ack. Методы по умолчанию сохраняют поведение остальных источников без правок.

### Воркер с хранилищем

**Решение**: источник с `AckPointSupport::Fixed` — хранилище:

| Ситуация | Что делает воркер |
|----------|-------------------|
| Момент ack | Всегда «после завершения», ack при приёме не выполняется (2.3.9 п. 6) |
| Терминальный исход | `complete`; кроме отмены остановкой и потери аренды — тогда ничего не пишется (2.3.20 п. 5) |
| Отравленное сообщение | `complete` со статусом «Ошибка» |
| Отказ по переполнению | `complete` со статусом «Отменена», `RejectedOverflow` (2.3.25 п. 5) |
| «В работе», «Ожидает повтора» | `progress` |
| Поток `notices()` | Отдельная задача воркера (см. ниже) |

Задача-слушатель `notices()`:
- `CancelRequested` → признак отмены с причиной «по запросу»;
- `LeaseLost` → признак отмены с причиной `LeaseLost`, WARN `lease/lost`, событие `LeaseLost`;
- `TakenOver` → WARN `lease/taken_over`, событие `LeaseTakenOver`.

Принудительное прерывание по льготному времени теперь действует для любой причины, кроме остановки.

`QueueHandle::fetch_status` — асинхронный статус: сначала реестр процесса, затем источник. Синхронный `status` остаётся локальным.

### Схема и SQL

**Решение**: `taskcraft_tasks` (PK `queue, id`; `task jsonb` — конверт `JsonCodec`; `state`, `attempt`, `retries`, `cancel_requested`, `next_delivery`, `owner`, `lease_until`, `reason jsonb`, `created_at`, `updated_at`) и `taskcraft_processes (id, seen_at)`. Создаются при старте под `pg_advisory_xact_lock`.

| Операция | SQL |
|----------|-----|
| Опрос | CTE `SELECT … FOR UPDATE SKIP LOCKED LIMIT 1` по кандидатам 2.3.25 п. 1, порядок `COALESCE(next_delivery, created_at), created_at`; `UPDATE … SET state = 'accepted', owner, lease_until RETURNING` конверт с актуальными `attempt`/`retries` (`task ‖ jsonb_build_object(...)`) и прежним владельцем |
| Постановка | `INSERT … ON CONFLICT DO NOTHING`; конфликт → состояние строки: терминальное — `Finished`, иначе `Duplicate` |
| `complete`, `progress`, `defer` | `UPDATE … WHERE owner = <этот процесс>` — потерявший аренду процесс ничего не перезапишет |
| Отмена | `queued`/`deferred` → `cancelled` с причиной («отменена»); удерживаемая → `cancel_requested = true` («отмена запрошена»); терминальная → «уже завершена» |

Время везде считает база (`now()`), не процессы.

**Обоснование**: `SKIP LOCKED` даёт эксклюзивный захват без блокировки соседей (критерий заявки №1). Условие на владельца в каждой записи — гарантия 2.3.20 п. 5 со стороны базы.

### Старт процесса

**Решение**: `PgStoreBuilder::connect(url)` / `with_pool(pool)`:
1. Схема.
2. Проверка идентификатора: отметка «жив» моложе двух интервалов → `ProcessIdTaken` (2.3.19 п. 5, критерий №44). Иначе отметка.
3. Возврат своих задач: удерживаемые строки с `owner = <этот процесс>` → `queued`, владелец и аренда сброшены, счётчики сохранены. INFO `recovery/recovered` по очередям (2.3.19 п. 1, критерий №43). С арендой тоже: процесс с тем же идентификатором — тот же владелец.
4. Фоновая задача обслуживания, тик — `min(heartbeat, alive_interval)`:
   - отметка «жив»;
   - продление аренды удерживаемых задач (`UPDATE … WHERE owner = <этот процесс> RETURNING id, cancel_requested`);
   - не вернувшиеся строки → `LeaseLost`;
   - `cancel_requested` → `CancelRequested`, один раз на задачу;
   - удаление терминальных задач старше срока хранения.

Ошибка обслуживания → WARN `source/store_error`. Задача обслуживания держит `Weak`, а `Drop` хранилища её прерывает.

**Обоснование**: проверка идентификатора при подключении — «второй не стартует» без новых ошибок монитора.

**Отклонение**: без аренды запросы отмены читаются раз в тик обслуживания, а не при каждом опросе (2.3.20 п. 7) — один запрос на тик вместо запроса на каждый опрос. Уточнение спецификации — при применении.

### Подключение и TLS

**Решение**: sqlx 0.9 с `postgres` и `runtime-tokio`, без возможностей по умолчанию. TLS для собственных подключений — возможности пакета `tls-rustls` / `tls-native-tls`. Готовый пул приносит свой TLS.

### Ограничения валидации

**Решение**: длительности > 0; heartbeat строго меньше половины аренды (2.10); идентификатор процесса непуст (`EmptyProcessId`).

## Risks / Trade-offs

| Риск | Последствия | Mitigation |
|------|------------|------------|
| Тесты на базе не запускаются локально | Отладка через CI | Job CI с `postgres:17`; логика уведомлений покрыта юнит-тестами |
| Без аренды отмена чужой задачи ждёт тика | Задержка до `alive_interval` | Документировано; с арендой — тик heartbeat |
| Хранилище требует `JsonCodec` | Другие кодеки не подойдут | Конверт `JsonCodec` нужен для `jsonb` и счётчиков |
| Лицензия `webpki-roots` (CDLA-Permissive-2.0) за `tls-rustls` | cargo-deny | Разрешена в `deny.toml` с комментарием |

## Тестирование

### Unit-тесты

| Что | Сценарий |
|-----|----------|
| Настройки | Heartbeat ≥ половины аренды, нулевые длительности, пустой идентификатор |
| Продление | Не вернувшиеся строки → `LeaseLost`; запрос отмены — один раз; без аренды ничего не теряется |
| Ядро | `InMemorySource::remove` → `Withdrawal`; все прежние тесты |

### Integration-тесты (`tests/store.rs`, PostgreSQL в CI)

| Критерий | Сценарий |
|----------|----------|
| Заявки №2 | Исходы записаны; повторная постановка завершённой — «уже завершена» |
| Заявки №1 | Два процесса опрашивают одну задачу — её получает ровно один |
| №44 | Второе подключение с живым идентификатором — `ProcessIdTaken` |
| №30 б, №43 | Без аренды: другой процесс не берёт задачи упавшего; перезапуск с тем же идентификатором возвращает их, вторая попытка |
| №31 | С арендой: после истечения задачу берёт другой процесс, счётчик сохранён, `TakenOver` |
| №45 | Аренда «Принятой» задачи перехвачена — задача отменена, строка не тронута |
| Заявки №3 | После срока хранения строка удалена, идентификатор снова свободен |
| Заявки №4 | Отмена чужой задачи — «отмена запрошена», владелец отменяет её, статус «Отменена» |
| №30 а | Настроек аренды нет вне пакета хранилища — по построению API |
