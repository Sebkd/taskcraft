## 1. Предложение

### Цель изменения

Дать журнальный источник для Kafka. У apalis такого источника нет, а модель «хранилище с удалением» к журналу не подходит. Первый потребитель читает задания из Kafka с выключенной автоматической фиксацией и фиксирует смещение вручную после приёма задачи на учёт.

Здесь ack — это фиксация смещения по правилу границы: задача, ещё не дошедшая до момента ack, удерживает фиксацию всех следующих задач раздела.

### Инициатор

Разработка первой версии taskcraft (ветка `taskcraft/sebkd-1`). Требования первого потребителя — спецификация, раздел 1.1.

### Объём реализации

Спецификация 0.1 уже описывает целевое поведение (раздел 1.1, «Статус реализации»). Эта заявка поведение не меняет, а реализует перечисленные разделы. Поэтому разделы 2–15 ниже содержат только уточнения спецификации; где их нет — «Нет изменений.».

**Реализует:**

- 2.6 «Пакет taskcraft-kafka»
- 2.8 «Источник Kafka»
- 2.12 — метаданные в заголовках сообщения
- 2.3.9 п. 5 — граница фиксации смещения

**Не входит:**

- Отложенный повтор — Kafka его не поддерживает (правило 2.3.6)

**Зависит от заявок:** `source-contract`, `worker-loop-and-supervision`, `ownership-and-recovery`

## 16. Рекомендации к критериям приёмки

Обязательны критерии спецификации №23 (раздел 3) — в той части, которую закрывает эта заявка. Дополнительно:

| # | КОГДА | ТОГДА |
|---|-------|-------|
| 1 | Потребитель передал в дополнительных свойствах включённую автоматическую фиксацию | Она принудительно выключена |
| 2 | Сообщение без ключа при функции идентификатора по умолчанию | Идентификатор сгенерирован, журнал WARN один раз на очередь |
| 3 | Сообщение с заголовком под зарегистрированным именем метаданных | Значение доступно обработчику как метаданные этого типа |
| 4 | Брокер недоступен | Ошибка источника, перезапуск по правилу 2.3.12, фиксации смещений нет |
| 5 | Два процесса одной группы потребителей | Разделы распределены Kafka; каждая задача исполняется одним процессом |
