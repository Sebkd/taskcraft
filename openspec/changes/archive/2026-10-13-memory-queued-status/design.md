## Context

`fetch_status` (`crates/taskcraft/src/handle.rs:177`) сначала спрашивает реестр, затем источник через `Port::status`. Для очередей на `PushSource` обёртка `Pushed` (`crates/taskcraft/src/backend.rs:142`) всегда отвечает `Ok(None)` — «неизвестна». А `InMemorySource` (`crates/taskcraft/src/memory.rs`) знает задачи, которые ещё не выданы опросом:
- `State::ready` — готовые к выдаче;
- `State::deferred: BTreeMap<(Instant, u64), Task>` — две разные группы:
  - поставленные на момент (`push_at`, попыток ещё не было, `attempt() == 0`);
  - возвращённые исходом «отложить» (`defer`, попытка уже была, `attempt() >= 1`).

Хранилище PostgreSQL отвечает: «В очереди» с моментом следующей доставки — для `push_at`, «Отложена» — после «отложить» (`crates/taskcraft-postgres/src/source.rs:403`, `with_times(created, None, next)`).

## Goals / Non-Goals

**Goals**
- `fetch_status` очереди на in-memory источнике отвечает о задачах, ещё не выданных опросом, так же, как хранилище.

**Non-Goals**
- История завершённых задач в памяти.
- Время постановки (`accepted_at`) для задач в источнике: in-memory источник его не хранит; поле остаётся пустым.

## Decisions

### D-1. Необязательный метод `PushSource::status`

```rust
/// What the source knows of a task it holds and has not handed out yet;
/// `None` when it does not hold it or keeps no such record (the default).
fn status(&self, id: &TaskId) -> impl Future<Output = Result<Option<TaskStatus>, Self::Error>> + Send {
    async { Ok(None) }
}
```

Метод с реализацией по умолчанию — совместимое дополнение: свои `PushSource` пользователей продолжают собираться. `Pushed::status` (`backend.rs:142`) вызывает его вместо `Ok(None)`.

### D-2. Ответ `InMemorySource`

Под замком состояния:
- задача в `ready` → `Queued`, попытка и счётчик повторов — из `Task`;
- задача в `deferred` с `attempt() == 0` → `Queued` с моментом доставки в `next_attempt_at`;
- с `attempt() >= 1` → `Deferred` с моментом следующей доставки;
- иначе — `None`. Это и выданная опросом, но ещё не принятая в реестр задача (её покажет реестр, как только примет).

Момент — `tokio::time::Instant`. В `SystemTime` переводится как «сейчас + остаток до момента» (насыщение к «сейчас» для прошедшего).

Поиск в `ready` и `deferred` — перебор. In-memory источник ограничен ёмкостью (по умолчанию 10 000), а статус — редкая операция. Отдельный индекс по идентификатору не заводится: он усложнил бы `remove` и `poll` ради редкого запроса.

### D-3. Тесты

В `memory.rs`, модульные:
1. Поставленная и не выданная задача → `Queued`, попытка 0.
2. `push_at` через час → `Queued`, `next_attempt_at` примерно через час.
3. Отложенная после попытки (`defer`) → `Deferred` с моментом.
4. Выданная опросом и неизвестная → `None`.

Сквозной (`tests/`): `QueueHandle::fetch_status` для задачи, поставленной в остановленную (не запущенную) очередь, → `Queued`.

## Risks / Trade-offs

- Короткое окно «выдана опросом, но ещё не в реестре»: ответ «неизвестна». Так и сейчас, окно не меняется.
