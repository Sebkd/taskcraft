## Context

`KafkaSource::ack` (`taskcraft-kafka/src/source.rs`) вызывает `consumer.commit(offsets, CommitMode::Async)`. librdkafka сообщает результат в `ConsumerContext::commit_callback`, а `Callbacks` его не реализует.

`Commits::acked` (`commits.rs`) записывает `committed = point` до отправки фиксации. Если фиксация не удалась, тот же `point` больше не отправляется: следующий ack раздела отправит фиксацию, только когда граница сдвинется дальше.

Ошибки фоновых операций источника воркер сейчас узнаёт только из опроса и ack; канал уведомлений (`Notice`) знает отмену и аренду.

---

## Goals / Non-Goals

**Goals:** отказ фиксации виден в журнале и метрике; точка фиксации раздела фиксируется снова при следующем ack.

**Non-Goals:** синхронная фиксация; перезапуск цикла приёма из-за отказа фиксации — следующий ack и так её повторит.

---

## Decisions

### `commit_callback` в `Callbacks`

**Решение**: при `Err` для каждого раздела из переданного списка смещений:
- WARN `source/commit_failed` с топиком, разделом, смещением и ошибкой — журнал пишет источник, он знает топик;
- `Commits::commit_failed(partition, offset)` — сбросить зафиксированную точку, если она не продвинулась дальше отказавшей;
- уведомление воркеру `Notice::SourceError(String)`.

`Callbacks` получает отправитель уведомлений; сам канал создаётся при построении источника, `notices()` отдаёт приёмник один раз (как в хранилище).

### Повтор фиксации

**Решение**: `Commits::commit_failed(partition, next)`: если `committed == Some(next - 1)` — сбросить `committed` в `None`. Следующий `acked` раздела вернёт текущую границу и отправит фиксацию снова. Более новая успешная фиксация (`committed > next - 1`) не трогается.

### Новое уведомление ядра `Notice::SourceError`

**Решение**: вариант `Notice::SourceError(String)` — фоновая ошибка источника. Слушатель воркера отправляет событие `SourceFailed`, то есть `taskcraft_source_errors_total` +1, и **не** перезапускает цикл приёма. Журнал пишет источник: у него больше подробностей.

**Обоснование**: метрика ошибок источника — общая для всех источников; хранилищу это уведомление тоже пригодится для ошибок обслуживания (`source/store_error`).

---

## Risks / Trade-offs

| Риск | Последствия | Mitigation |
|------|------------|------------|
| Повтор фиксации после сбоя ребаланса для отозванного раздела | Попытка зафиксировать чужой раздел | `Commits` уже забыл отозванный раздел; `commit_failed` для неизвестного раздела ничего не делает |

## Тестирование

| Критерий заявки | Тест |
|-----------------|------|
| №1 | unit `source.rs`: `commit_callback` с ошибкой → уведомление `SourceError`; WARN `source/commit_failed` |
| №2 | unit `commits.rs`: после `commit_failed` следующий `acked` возвращает текущую границу |
| №3 | unit: `commit_callback` с `Ok` — ни уведомления, ни изменений |
| — | Ядро: уведомление `SourceError` → событие `SourceFailed`, цикл приёма не перезапущен |
