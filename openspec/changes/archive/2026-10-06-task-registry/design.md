## Context

Воркер уже исполняет задачи с повторами, пулами и политикой переполнения (`worker.rs`). Но по идентификатору к задаче обратиться нельзя: ни постановки из кода через очередь, ни статуса, ни отмены. У каждой задачи уже есть свой токен отмены — `drain_cancel.child_token()`, — но выставляет его только остановка по таймауту, а обработчик этот токен не видит.

Модель для ответов уже есть (`task-model-and-lifecycle`): `PushOutcome`, `TaskStatus`, `FinishReason::CancelledByUser`. Источник умеет приём постановки с проверкой идентификатора (`Source::push` → `PushResult::{Stored, Duplicate, Full}`) и проверку переопределения ack (`Capabilities::check_ack_override`).

Требования:

- **2.3.11.** Реестр живых задач очереди. Проверка и запись — одна неделимая операция. Задача снимается на каждом терминальном переходе и при «Отложена».
- **2.3.15.** Свой признак отмены у каждой задачи. Обработчик видит его через извлекаемое значение; по истечении льготного времени попытка прерывается. Итог — «Отменена» с причиной.
- **2.1.2.1.** Постановка: остановка, поддержка постановки источником, переопределение ack, кодирование, запись с проверкой идентификатора.
- **2.1.2.14.** Статус по идентификатору.
- **2.1.2.15.** Отмена по идентификатору, включая задачу «В очереди» in-memory источника.
- **Критерии:** спецификация №17, №18, №19, №28, №38 (без хранилища), №42; критерий заявки №1.

Ветки хранилища («уже завершена», отмена задачи другого процесса) — в `durable-task-store`.

## Goals / Non-Goals

**Goals:**

- `TaskRegistry` очереди: состояние, номер попытки, счётчик повторов и времена у каждой живой задачи; признак отмены задачи; признак «очередь останавливается».
- `QueueHandle` — клонируемая ручка очереди с операциями `push`, `status`, `cancel`. Получается из очереди до регистрации в мониторе.
- Извлекаемое значение `Cancel` — признак отмены задачи в обработчике.
- Отмена задачи в любом состоянии: в источнике («В очереди»), в ожидании слота или пулов, в паузе повтора, в работе (кооперативно, затем прерывание по льготному времени).
- Дубль по идентификатору при опросе: подтверждается как дубль, задача не исполняется (2.1.2.2 шаг 2).

**Non-Goals:**

- Хранилище и ответ «уже завершена» — `durable-task-store`.
- Таймаут попытки — `ownership-and-recovery` (будет использовать тот же признак отмены).

## Decisions

### Реестр — `HashMap` под мьютексом внутри очереди

**Решение**:
- `TaskRegistry` — `Arc<Mutex<Inner>>`.
- `Inner` хранит:
  - `tasks: HashMap<TaskId, Entry>`;
  - `closing: bool` — очередь останавливается.
- `Entry` хранит:
  - `state`, `attempt`, `retries`;
  - `accepted_at`, `attempt_started_at`, `next_attempt_at`;
  - `cancel: CancellationToken`;
  - `cancel_reason: Option<FinishReason>`.
- Операции (`pub(crate)`):
  - `try_accept(id, token) -> Result<(), TaskState>` — запись или существующее состояние; неделимо под мьютексом;
  - `update(id, f)`;
  - `remove(id)`;
  - `status(id)`;
  - `cancel(id, reason) -> Option<TaskState>`;
  - `set_closing()`, `is_closing()`.
- Реестр создаётся вместе с очередью, его `Arc` хранят и воркер, и все ручки.

**Обоснование**: 2.3.11 п. 1 (неделимость) и п. 2 (снятие на каждом терминальном пути). Мьютекс с короткими участками — как в `InMemorySource`. Память занимают только живые задачи (инвариант 1.3.9, критерий №18).

**Альтернативы**:
- `DashMap` — отклонено: новая зависимость ради того, что даёт мьютекс; конкуренция за реестр ничтожна рядом с исполнением задач.

### Ручка очереди `QueueHandle`

**Решение**: `Queue::handle() -> QueueHandle<S, C, Args>` — клонируемая ручка: `Arc` источника, кодека и реестра, плюс возможности источника. Операции:

- **`push(task) -> Result<PushOutcome, PushTaskError>`** (2.1.2.1):
  1. `registry.is_closing()` → `Err(Stopping)` («queue is stopping»).
  2. Источник не принимает постановку → `Err(Unsupported)` («source does not accept pushes»).
  3. `check_ack_override` → `Err(AckOverride)`.
  4. Живая задача в реестре → `Ok(AlreadyRunning { state })`.
  5. `codec.encode(task)` → при ошибке `Err(Encode(CodecError))` (незарегистрированный тип метаданных — сценарий 2.2.10, критерий №28).
  6. `source.push(id, message)`:
     - `Stored` → `Ok(Enqueued)`;
     - `Duplicate` → `Ok(AlreadyRunning { state: Queued })`;
     - `Full` → `Ok(Rejected { SourceFull })`;
     - `PushError::Closed` → `Err(Stopping)`;
     - `PushError::Source(e)` → `Err(Source(e))`.
- **`status(id) -> Option<TaskStatus>`** — снимок записи реестра; `None` («неизвестна»), если записи нет.
- **`cancel(id) -> CancelOutcome`**:
  - есть в реестре → признак отмены задачи с причиной `CancelledByUser`, журнал INFO `task/cancel_requested`, `CancelRequested`;
  - нет в реестре и источник умеет убрать задачу (`Source::remove`) → `Cancelled`;
  - иначе → `Unknown`.

`PushTaskError` — неуниверсальное перечисление, ошибка источника хранится как `BoxError`. Так тип ручки не зависит от типа ошибки источника в сигнатурах ошибок.

**Обоснование**: 2.5 «Очередь» — постановка, статус, отмена. Ручка берётся до регистрации, потому что очередь уходит в монитор по значению, а работать с ней нужно и после запуска.

**Альтернативы**:
- Методы на мониторе по имени очереди — отклонено: потеря типа аргументов (`push` требует `Task<Args>`) и поиск по строке на каждый вызов.

### `Source::remove` — убрать ещё не выданную задачу

**Решение**: новый необязательный метод контракта `remove(&self, id) -> impl Future<Output = Result<bool, Self::Error>>`; по умолчанию `Ok(false)`. `InMemorySource` убирает задачу из готовых или отложенных, если она ещё не выдана, и освобождает идентификатор.

**Обоснование**: 2.1.2.15 шаг 4, переход 2.4.1.13, критерий заявки №1. Метод с реализацией по умолчанию не ломает собственные источники.

### Признак отмены и прерывание

**Решение**:
- `TaskRequest` получает признак отмены задачи: `TaskRequest::with_cancel(token)`. Новое извлекаемое значение `Cancel(CancellationToken)`; у запроса, созданного без признака, токен никогда не срабатывает.
- `execute` берёт токен задачи из реестра.
  - **Ожидание слота, пулов и пауза повтора:** `select!` с токеном. Сработал → «Отменена» с причиной из реестра (`CancelledByUser`) и ack по моменту очереди (2.1.2.15 п. 8). Результат — `Finished`, а не `CancelledWaiting`: это не остановка.
  - **Попытка:** `select!` между попыткой и «токен сработал, затем прошло льготное время». Второе → попытка уничтожается (принудительное прерывание), журнал WARN `task/aborted`, «Отменена». Если обработчик завершился сам до конца льготного времени — «Отменена» по 2.3.15 п. 4 (кроме паники).
- Остановка по таймауту по-прежнему отменяет токены через родительский `drain_cancel`; причина в реестре пуста → `CancelledByShutdown`, как сейчас.
- Прерывание по льготному времени в `execute` — только для отмены по запросу; при остановке льготное время отсчитывает `drain`, как раньше.
- Ошибка `Source::remove` при отмене → ответ «неизвестна», журнал WARN `source/remove_failed`.

**Обоснование**: 2.3.15 пп. 1–4 и критерий №19. Прерывание в самой задаче исполнения не трогает остальные задачи `JoinSet`.

### Воркер и реестр

**Решение**:

| Когда | Что |
|-------|-----|
| Приём задачи из опроса | `try_accept` **до** ack «после приёма». Идентификатор занят → ack сообщения как дубля, DEBUG `task/duplicate`, задача не исполняется (2.1.2.2 шаг 2, инвариант 1.3.8) |
| Переходы `execute` | `registry.update`: «В работе» — номер попытки и время начала; «Ожидает повтора» — время следующей попытки; «Принята» — сброс времени начала |
| Терминальный переход и «Отложена» | `registry.remove` (2.3.11 п. 2) |
| Сигнал остановки | `registry.set_closing()` — постановка дальше отвечает «очередь останавливается» (2.3.14 п. 3) |

## Risks / Trade-offs

| Риск | Последствия | Mitigation |
|------|------------|------------|
| Окно между выдачей опросом и `try_accept` | Параллельная постановка с тем же идентификатором попадёт в источник | In-memory источник держит идентификатор до ack, а ack идёт после `try_accept` — окно закрыто для in-memory. Для журналов дубль гасится при следующем приёме |
| Задача «В очереди» не видна в `status` | Статус «неизвестна» для поставленной, но не выданной задачи | Совпадает с 2.1.2.14 без хранилища: реестр знает только принятые; хранилище расширит |
| Прерывание по льготному времени уничтожает future обработчика | Незавершённые побочные эффекты | Это и есть принудительная отмена 2.3.15 п. 3; кооперативный путь — через `Cancel` |

## Архитектура

### Компонентная диаграмма

```
QueueHandle ──push──► check(closing, caps, ack) ─► реестр? ─► codec.encode ─► source.push ─► PushOutcome
            ──status─► реестр ─► TaskStatus | None
            ──cancel─► реестр: token.cancel(User) | source.remove | Unknown
                              ▲                    ▲
worker: try_accept ───────────┘                    │
execute: update(state, attempt, времена) ── select{ попытка | cancel+grace } ── remove на финише
```

## Детали реализации

### Алгоритмы

```
try_accept(id, token):
  под мьютексом: есть id → Err(state); иначе вставить Entry{Accepted, token} → Ok

cancel(id):
  под мьютексом: есть → entry.cancel_reason = CancelledByUser; token.cancel(); вернуть state
  нет → source.remove(id) → true: Cancelled; false: Unknown

попытка(execute):
  select { исход = попытка → исход;
           token.cancelled() затем sleep(grace) → прерывание: «Отменена», WARN task/aborted }
```

### Обработка edge cases

| Ситуация | Поведение |
|----------|----------|
| Повторная отмена | Тот же ответ, ничего не меняется (идемпотентность) |
| Отмена паникующей задачи | «Паника» остаётся «Паникой» (2.3.15 п. 4) |
| Отмена задачи в паузе повтора | «Отменена» сразу, ack по моменту очереди |
| Отмена задачи с ack «после приёма» | Ack уже был; итог «Отменена» |
| Постановка после «закрыт» источника | `PushError::Closed` → «очередь останавливается» |
| Дубль из опроса | Ack, DEBUG `task/duplicate`, слот освобождается |
