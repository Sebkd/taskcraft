## Context

- `rust-version = "1.99"` задан в рабочем пространстве (`Cargo.toml:8`), все пакеты берут его (`rust-version.workspace = true`).
- `.clippy.toml`: `msrv = "1.99"` — для всех пакетов сразу; clippy предлагает возможности до 1.99 и в ядре.
- CI: задание «MSRV (1.99)» — `cargo test --workspace --all-features --locked` на 1.99.
- Проверка 2026-10-30 (временная правка, откатана): ядро с `rust-version = "1.96"` на 1.96.1 — `cargo test -p taskcraft --all-features --locked` зелёный, `cargo build -p taskcraft --all-features --examples --locked` и `cargo build -p taskcraft --locked` собираются, предупреждений cargo о `rust-version` зависимостей нет.
- Версия общая для рабочего пространства (`version.workspace = true`, 0.4.0); пакеты зависят от ядра `version = "0.4.0"`.

## Goals / Non-Goals

**Goals**
- `taskcraft` объявляет и держит 1.96: CI ловит возможность новее.

**Non-Goals**
- Снижение версии `taskcraft-kafka`, `taskcraft-postgres`, `readme-check`, `taskcraft-benches`.

## Decisions

### D-1. Своя `rust-version` у ядра

`crates/taskcraft/Cargo.toml`: `rust-version = "1.96"` вместо `rust-version.workspace = true`. Рабочее пространство остаётся на 1.99 для остальных пакетов. README ядра: значок и строка «Rust 1.96 or newer».

### D-2. Clippy — по версии пакета

`msrv` убирается из `.clippy.toml`: clippy берёт `rust-version` каждого пакета. Ядро — 1.96, остальные — 1.99. Иначе clippy будет предлагать в ядре возможности 1.97–1.99, а задание на 1.96.1 падать уже после правки по совету линтера.

### D-3. Задание CI «MSRV core (1.96.1)»

```yaml
msrv-core:
  name: MSRV core (1.96.1)
  steps:
    - dtolnay/rust-toolchain@1.96.1
    - cargo test -p taskcraft --all-features --locked     # log, metrics, test-util
    - cargo build -p taskcraft --all-features --examples --locked
    - cargo build -p taskcraft --locked                    # без возможностей
```

Задание «MSRV (1.99)» остаётся для всего рабочего пространства.

### D-4. Версия и выпуск — все три пакета 0.4.1 (решено 2026-10-30, вариант 2)

Снижение минимальной версии компилятора — совместимое изменение, это 0.4.1. Пакеты потребителю не нужны и не меняются. Варианты:

1. **Выпустить только `taskcraft` 0.4.1** (рекомендую). У ядра своя `version = "0.4.1"`, остальные пакеты остаются 0.4.0 и зависят от ядра `version = "0.4.0"` — с 0.4.1 совместимо. На crates.io меняется только ядро.
2. **Выпустить все три 0.4.1**, как раньше, единой версией. У пакетов не меняется ничего, кроме номера.

### D-5. `MIGRATION.md`

Пункт в списке: «0.4.0 → 0.4.1 (compatible): `taskcraft` builds on Rust 1.96; the Kafka and PostgreSQL packages stay on 1.99». CHANGELOG в проекте не ведётся (решение проекта); запись — в `MIGRATION.md`.

## Risks / Trade-offs

- Обновление зависимости ядра, которой нужен компилятор новее 1.96, роняет новое задание CI. Это и есть цель: ограничение видно до выпуска. Решение — придержать версию зависимости в `Cargo.lock` или по согласованию поднять минимальную версию.

## Open Questions

Нет. D-4: выпуск всех трёх пакетов 0.4.1 единой версией, как раньше.

## Затронутые примеры

Не меняются; примеры ядра собираются новым заданием CI.

## Тестирование

- Новое задание CI зелёное; локально — те же три команды на 1.96.1.
- Всё остальное CI без изменений: clippy (с msrv по пакетам), тесты, `semver-checks`.
