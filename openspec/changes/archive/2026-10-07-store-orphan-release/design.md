## Context

`crates/taskcraft-postgres/src/store.rs`:

- `claim_process_id` под `pg_advisory_xact_lock(hashtext(process_id))` отказывает идентификатору с отметкой «жив» моложе двух интервалов (`ProcessIdTaken`). Иначе ставит отметку.
- `give_back(pool, process_id)` возвращает задачи владельца в «В очереди» (`accepted`, `running`, `retry_waiting`). Сохраняются `attempt` и `retries`, по очередям пишется INFO `recovery/recovered`.
- **Без аренды** задачи другого владельца не трогает никто (2.3.19 п. 1). Без рестарта владельца они висят «в работе».

## Decisions

### D-1. `PgStore::release_process(process_id) -> Result<u64, PgStoreError>`

- **Где выполняется:** в транзакции под той же блокировкой, что `claim_process_id` (`hashtext(process_id)`). Так операция не гоняется со стартом этого процесса.
- **Живой процесс** — отметка моложе двух интервалов «жив» **этого** хранилища — даёт `PgStoreError::ProcessIdTaken(id)`, задачи не трогаются (критерий №2). Интервал чужого процесса неизвестен, отсюда допущение: интервалы у процессов одного развёртывания одинаковые. Это записывается в документации.
- **Свой идентификатор** — та же ошибка: процесс жив.
- **Иначе** — то же обновление, что `give_back`:
  - задачи владельца уходят в «В очереди», номер попытки и счётчик повторов сохраняются;
  - возвращается их число;
  - журнал INFO `recovery/released`: `tasks released: owner={}, count={}` (критерий №1).
- **Отметка «жив» выведенного процесса не удаляется.** Если он всё же стартует, то стартует как обычно, и забирать ему уже нечего.
- **Пробуждения нет:** вернувшиеся задачи процессы получат ближайшим опросом по стратегии.
- **`give_back` и `release_process`** делят одну функцию возврата. Различаются журнал и проверка «жив».

### D-2. Предупреждение при старте о молчащих владельцах

- **Порог** — `PgStoreBuilder::stale_owner_warning(Duration)`, по умолчанию 1 ч, ноль — ошибка конфигурации.
- **Где:** при старте, после `give_back`, только **без аренды** — с арендой такие задачи заберут по истечении аренды сами.
- **Запрос** — задачи в `accepted`, `running`, `retry_waiting` с владельцем, отличным от своего, у которого:
  - отметки «жив» нет;
  - либо она старше порога.

  Группировка по владельцу. Это редкий запрос при старте, он идёт по индексу владельца.
- **Журнал** — WARN `recovery/stale_owner` на каждого владельца: `tasks held by a silent process: owner={}, count={}, silent_for={}`. Здесь `silent_for` — время с последней отметки (`{:?}` длительности), без отметки — `unknown`.
- В сообщении есть подсказка: сделать `release_process` или включить аренду. Подсказка идёт вторым предложением в тексте записи: формат `key=value` её допускает после аргументов.

### D-3. Документация

- **README пакета, раздел «Retiring a process»:**
  - платформам с переменным числом процессов (автомасштабирование, смена имён подов) — включать аренду;
  - без аренды — вызывать `release_process` для выведенного идентификатора.
- **Документация метода:** допущение об одинаковом интервале «жив».

### Тесты (пакет хранилища, база через `TASKCRAFT_POSTGRES_URL`)

- **Журнал в тестах.** Нужен перехват журнала: дев-зависимость `tracing-subscriber` (`registry`). Она уже есть в рабочей области и в `supply-chain`. Перехват — свой `Layer`, собирающий `event`, `action`, `message`.
- **Критерий №1:**
  - процесс P захватывает две задачи (помощник `claim_and_crash`, аренда выкл.) и пропадает;
  - после 2,5 интервалов процесс Q вызывает `release_process(P)` → 2;
  - задачи «В очереди», `attempt = 1`;
  - INFO `recovery/released`.
- **Критерий №2:** P жив (хранилище держится) → `ProcessIdTaken`, задачи «В работе».
- **Критерий №3:**
  - P молчит;
  - процесс R стартует с порогом 300 мс → WARN `recovery/stale_owner` с `owner=P, count=2`;
  - с арендой предупреждения нет.

## Risks / Trade-offs

| Риск | Последствия | Mitigation |
|------|------------|------------|
| Администратор вызвал `release_process` для процесса, который жив, но с бóльшим интервалом «жив» | Задачи живого процесса уйдут другим, то есть двойное исполнение | Документация: одинаковые интервалы в развёртывании; порог «жив» — два интервала, как при старте |
