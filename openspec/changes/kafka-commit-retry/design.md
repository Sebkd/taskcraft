## Context

- `KafkaSource::ack` (`crates/taskcraft-kafka/src/source.rs:348`) спрашивает у `Commits::acked`, сдвинулась ли граница раздела. Если сдвинулась — фиксирует асинхронно (`CommitMode::Async`).
- Отказ брокера приходит в `Callbacks::commit_callback`: WARN `source/commit_failed`, `Commits::commit_failed`. Тот сбрасывает `Partition::committed` в `None`, если отклонена последняя отправленная граница.
- Повтор сейчас есть только в `acked`: следующий ack раздела пересчитает границу, и `committed == None` позволит зафиксировать её снова.
- Если ack больше не будет, граница не фиксируется. Состояние «`committed == None`, а `tracker.commit_point()` уже есть» бывает только после отказа: после ack с точкой фиксации `committed` всегда выставлен.

Опрос источника (`KafkaSource::poll`) идёт непрерывно: пустой ответ — не реже раза в `max_wait` (по умолчанию 1 с), и воркер тут же опрашивает снова.

## Goals / Non-Goals

**Goals**
- Отклонённая граница фиксируется снова без нового ack — на опросе, не раньше паузы после отказа.

**Non-Goals**
- Синхронная фиксация при остановке (BL-38).
- Изменение момента ack и границы фиксации.

## Decisions

### D-1. Повтор на опросе, с паузой после отказа

- `Commits::commit_failed(partition, next, now)` запоминает момент отказа: `Partition::retry_at = now + RETRY_PAUSE`, где `RETRY_PAUSE = 1 с`.
- Новый `Commits::retry(now) -> Vec<(i32, i64)>` отдаёт разделы, у которых одновременно:
  - `committed == None`;
  - есть точка фиксации;
  - наступил `retry_at`.

  Каждому выставляет `committed` (как `acked`) и отдаёт следующее смещение.
- `KafkaSource::poll` в начале вызывает `retry(Instant::now())` и, если список не пуст, фиксирует его асинхронно одним `TopicPartitionList`. Новый отказ снова придёт в `commit_callback`, и круг повторится.

Пауза нужна, чтобы при недоступном координаторе не слать фиксацию и WARN на каждом опросе. При потоке сообщений опрос идёт на каждое сообщение — без паузы были бы десятки повторов в секунду. Итог — одна попытка в секунду на раздел, и на каждую попытку по-прежнему один WARN.

`Commits` остаётся без часов: момент передаётся снаружи, поэтому логика проверяется модульными тестами.

### D-2. Ошибка самой отправки

Немедленная ошибка `consumer.commit` при повторе (локальная, не от брокера) — та же, что в `ack`: опрос возвращает ошибку источника (перезапуск по правилу 2.3.12). Граница остаётся к повтору.

### D-3. Тесты

**Модульные** (`commits.rs`):
1. Отказ последней границы → `retry` до паузы пуст, после паузы отдаёт `(раздел, граница)`. Повторный `retry` пуст: граница снова «отправлена».
2. Отказ, затем ack более поздней задачи (фиксируется новая граница), затем `retry` — пусто. Старая граница не возвращается.
3. Отказ по разделу, который отозван, — `retry` пуст.

**Тест брокера** (`tests/broker.rs`): ставлю глобальный подписчик `tracing`, который пишет в общий буфер. Если ожидание фиксации в `tasks_run_and_offsets_are_committed` не дождалось, сообщение утверждения содержит последнее прочитанное смещение и строки `source/commit_failed` из буфера. Так в следующий раз причина будет видна в аннотации CI.

### D-4. Версия

Внутреннее исправление пакета, API тот же. Выпуск 0.3.2.

## Risks / Trade-offs

- Пока координатор недоступен, WARN пишется раз в секунду на раздел. Это сигнал эксплуатации, а не шум: фиксация действительно не проходит.
