## 1. Предложение

### Цель изменения

Дать стандартный набор метрик очереди и вывести его наружу двумя путями. Сейчас каждый сервис первого потребителя заводит свои счётчики принятых, отказанных, паник и ошибок цикла. Библиотека публикует их сама; сервис добавляет только доменные метрики.

Первый путь — адаптер на фасаде `metrics`, второй — наблюдатель для собственного реестра метрик потребителя. Ряды у обоих путей одинаковые.

### Инициатор

Разработка первой версии taskcraft (ветка `taskcraft/sebkd-1`). Требования первого потребителя — спецификация, раздел 1.1.

### Затронутые компоненты

- [x] Ядро `taskcraft`: наблюдатель, адаптер `metrics` (возможность сборки), спаны tracing

### Приоритет

средний

### Обратная совместимость

Да: новая функциональность, публичных версий библиотеки ещё нет.

### Объём реализации

Спецификация 0.1 уже описывает целевое поведение (раздел 1.1, «Статус реализации»). Эта заявка поведение не меняет, а реализует перечисленные разделы. Поэтому разделы 2–15 ниже содержат только уточнения спецификации; где их нет — «Нет изменений.».

**Реализует:**

- 2.3.22 — метрики двумя путями
- 2.9 — журнал, включая «Как приложение видит журнал»: цель `taskcraft::*`, библиотека не ставит подписчика, возможность сборки `log`
- 4.4 — трассировка, стандартные и вычисляемые метрики

**Не входит:**

- События добавляются по мере реализации заявок, которые их порождают

**Зависит от заявок:** `task-model-and-lifecycle`

## 16. Рекомендации к критериям приёмки

Обязательны критерии спецификации №32, №34 (раздел 3) — в той части, которую закрывает эта заявка. Дополнительно:

| # | КОГДА | ТОГДА |
|---|-------|-------|
| 1 | Включён адаптер `metrics` и любой экспортер | Имена и теги рядов совпадают с таблицей 4.4.2 |
| 2 | У задачи есть метаданные `trace_parent` | Спан попытки связан с родительским спаном |
| 3 | Наблюдатель паникует на событии | Задача не затронута, журнал WARN |
| 4 | Приложение ставит `tracing-subscriber` с фильтром `taskcraft=debug` | Видны события приёма, старта и исхода попыток; цели всех событий начинаются с `taskcraft` |
| 5 | Приложение на `log` + env_logger, включена возможность `log`, подписчика tracing нет | События библиотеки видны как записи `log` |
| 6 | Подписчик не установлен | Библиотека не печатает ничего и не ставит подписчика сама |
